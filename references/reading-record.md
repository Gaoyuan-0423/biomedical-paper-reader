# 逐图阅读记录与完成检查

有图的阅读任务在材料盘点时建立此工作记录，随后复用并更新。它补充已有主张索引，不再新建平行科学证据表。完整精读要求已有各主图、补图及 Extended Data 至少概览；深入核查的面板由主张、对照和待解问题决定。速读／专题只要求所选图及必要依赖，未读项在工作记录中列清。

此记录默认独立于阅读报告。正文围绕研究问题、方法目的、结果和论证组织内容，不强制展示查看事件、覆盖表、页号清单、核查层级或记录校验结果，也不为记录要求额外生成可读附件。用户要求核查报告或附件时，再呈现相应记录。关键材料未读、不可得或不清楚若影响科学判断，仍须在对应论点说明具体限制；整体交付受限时简短说明适用范围。

## 状态与实际动作

| 状态 | 要记录的事实 | 不能据此声称 |
|---|---|---|
| `pending` | 图号、来源、是否在范围内，以及尚未查看的原因 | 已读图、图中显示、图像已核查 |
| `caption_only` | 已读图注位置；图像仍未看 | 视觉确认、由图像发现的冲突 |
| `overview` | 成功查看记录与简短观察；图号、布局和总体比较可辨认 | 所有面板、精确数字都已核查 |
| `panels` | 概览记录、实际核查的面板及其标签／方向／数值观察 | 未列面板也已核查 |
| `unreadable` | 具体来源或工具障碍、已尝试的可用替代方式及剩余限制 | 已查看或已验证；把单纯未打开称为读不清 |

转换、复制、裁剪、保存或在报告中嵌入图片，都不构成查看动作。只有图像通过工具真实返回且被阅读者观察后才推进状态，无需为证明该动作另加面向用户的查看声明。失败调用不能算查看成功。整图不清时可读取原图或 PDF 页；没有更清晰来源则限定具体主张，不猜图。

先按正文、完整图注及可用文件盘点图号；图注 PDF 可能只有文字，不能当作补图图像。清单与 Methods／Results 引用核对，不能仅列准备看过的几张。每个核心主张关联相关主图、补图、方法和必要对照；QC、批次校正、细胞注释及阴性结果同样影响解释。

## 轻量记录格式

有文件工具时在论文工作目录的独立工作记录位置维护 `reading-record.json`；无文件工具时保留等价工作记录，并对照实际调用检查。不要求安装数据库、固定图像工具或依赖库。图像来源、裁图与 PDF 页序在工作记录中可追溯；源版本改变时回查受影响项。该 JSON 是机器工作记录，不要求在报告中展示或作为可读附件交付。

JSON 使用以下字段。`figures` 列盘点到的全部图；`required` 在速读／专题中表示选择的图及必要依赖，完整精读不能用 `false` 跳过已有图。

```json
{
  "schema_version": 1,
  "mode": "full",
  "delivery_status": "complete",
  "inventory_complete": true,
  "figures": [
    {
      "id": "Fig. 1",
      "role": "main",
      "source": "main.pdf",
      "status": "panels",
      "required": true,
      "view_event_ids": ["view-01"],
      "observation": "第4页整图A–C；B的横轴是患者组，纵轴为评分，红组高于蓝组。",
      "checked_panels": ["B"],
      "limitation": ""
    }
  ],
  "claims": [
    {
      "id": "E1",
      "kind": "result",
      "figure_ids": ["Fig. 1"],
      "basis": "image",
      "status": "supported",
      "comparison_checked": true,
      "verification_note": "B的分组、轴定义与相关方法一致；仅核查图示方向。"
    }
  ],
  "report_assertions": []
}
```

`mode` 为 `full`／`quick`／`focused`，`delivery_status` 为 `complete`／`limited`。未完成图像步骤的记录用 `limited`，不能仅保留默认 `complete`。`inventory_complete` 只表示已完成实际材料盘点，不表示阅读完成。

`claims` 可复用工作证据索引的 ID，不要求报告展示对应编号：`kind` 为 `result`／`criticism`／`recommendation`，`basis` 为 `text`／`image`，`status` 为 `supported`／`unresolved`／`conflict`。仅据正文或图注的主张用 `text`。已确认冲突需要比较条件核对与复核说明；比较身份未确定用 `unresolved`。字段完整不证明判断正确，科学含义仍按[证据规则](evidence-rules.md#图像含义与冲突确认)复核。

`report_assertions` 仅对应阅读报告或用户请求的核查附件中**实际存在的已读、已查看或覆盖声明**。报告只有科学解释和自然图号引用、没有这类声明时，保留空数组；不要为校验而生成公开覆盖声明。若确有声明，不能漏列或降低其声称的范围，`report_location` 可写文件及具体位置，例如“核查附件.md：覆盖表 Fig. 1 行”。自然的“Fig. 1B 显示……”与科学结果本身仍需真实图像依据，但不需要被改写成面向读者的查看声明。明确汇总概览数时计 `overview` 与 `panels`，面板核查数只计 `panels`；`caption_only` 不进入视觉计数。

JSON schema 保持版本1及上述字段。文件/裁图对应等扩展元数据可放在独立工作记录中，不新增字段来改变本 schema，也不为改变正文风格修改校验器。

## 查看记录与校验

查看事件引用来自本次实际调用的标识或稳定顺序编号，并与源文件／页／裁图关联。宿主提供原始调用日志时，从成功的图像返回事件提取校验输入；保留原日志位置便于复查。无需重放图片或向外部上传文件。

标准化事件 JSONL 每行一个事件：

```json
{"event_id":"view-01","kind":"image_view","success":true,"figure_ids":["Fig. 1"]}
```

只有工具真实返回图像、且阅读者实际观察的动作使用 `image_view`；转换或复制分别使用 `convert`／`copy`。同一次返回确实包含多个完整图时可关联多个图号。转换出的文件路径与图号需先对应，不能把任意成功事件绑定成看过另一张图。标准化事件须来自真实调用结果；填写者自报的事件不能冒充独立导出的宿主日志。事件文件留在工作记录中，不要求公开展示。

有 Python 标准库环境时使用[记录校验器](../scripts/check_reading_record.py)：

```bash
python3 <skill目录>/scripts/check_reading_record.py reading-record.json
python3 <skill目录>/scripts/check_reading_record.py reading-record.json --events image-events.jsonl
```

无事件文件时只检查记录结构、覆盖及实际存在的声明的一致性，不能证明原始工具动作。提供真实事件文件时另外检查成功图像返回、图号匹配与虚报动作；仍不能证明读图的科学判断正确。没有 Python 时按相同条件人工对照，不因此停止已获授权的阅读。用户未要求核查报告时，不将校验输出复制进阅读报告。

该校验也不评价是否解释了研究目的、方法输入输出、设计与论证衔接。报告即使每张图都真实看过，仍可能只是读图笔记；完整精读另外按[逐图解释检查](report-template.md#逐图解释的交付检查)审阅正文，不把动作校验结果称为“精读质量通过”。

## 写作与交付条件

- 完整精读：清单盘点完成，已有各图均已概览，必要面板和关键批评已核查／复核；报告或核查附件若实际包含阅读/覆盖声明，须与工作记录一致。少数面板无法读清时在对应论点限定相关数字，不把概览写成逐面板确认。
- 速读／专题：所选图及必要依赖已查看，准备引用的数字和批评有相应核查；未选图不替其背书。不能因图组未选就跳过目标结论所需对照。
- 有范围内可读图待看：继续读取。上下文不足时保存记录分批续做，不以已有若干发现作为完成依据。
- 来源、格式或工具障碍确实无法解决：工作记录标 `limited`；在受影响论点说明具体材料缺口与判断边界，整体不足影响阅读判断时在开篇简短说明适用范围。详细未完成项和失败步骤留在工作记录，不要求正文另列资源状态或覆盖表。一致性检查通过不代表完整精读完成。用户明确缩小范围时同步模式／范围，不悄然缩小后继续声称全部核验。
- 记录与报告不一致、未查看却作视觉判断、已确认冲突未核对比较条件：修正或继续核查后再交付。文件存在、链接有效、报告篇幅足够均不能替代这些条件。

阅读记录与科学批评一起更新：复核发现读错标签、不同统计层级或不同比较时，撤回相应冲突，同步相关结果、阅读建议、局限和工作索引。已有公开核查附件或覆盖声明时也同步；默认报告不需要冲突计数、证据表或附件表。
