# 报告模板与写作职责

以下定义完整精读的写作职责，可按信息量合并重复章节。速读和专题按 [模式与语言适配](reading-modes.md) 缩小实际读取及输出范围，不先完成全文分析再缩写。方括号说明填写职责，实际报告不保留模板占位。不存在或无法核查的内容按证据规则标注，不强求固定字数。

**短材料例外：** 若只有摘要、二手短片段且原文无法获取，保留导读、来源范围、可支持的内容、关键缺口、必要的借鉴与资源状态即可。可合并下述章节，避免逐项重复“无法核查”。没有实际图表或结果细节时，不为完成格式生成六段逐图分析；只有候选线索时，研究借鉴以最值得核查的下一步为限。完整报告的长度应来自真实证据，而不是模板空缺。

## 开篇导读

以用户选择的语言写具体标题，说明研究对象、切入方式或主要发现。默认中文；明确英文时所有报告说明使用自然学术英文，保留原题与实体名。避免标题中把推断写成定论。

- **一句话发现：** 研究解决了什么，核心结果是什么，限定于何种材料或模型。
- **阅读建议：** 精读 / 选择性阅读 / 暂缓；给最关键的依据。材料不足时判断标“暂定”，必要时写“无法充分判断”。
- **适用场景：** 用“如果研究……，本文的……值得借鉴”表达。没有用户方向时不虚构个性化相关度。
- **本文看点：** 少量并列要点，通常三条；信息不足时减少，不与全文总结重复展开。

## 文章信息

| 项目 | 内容 |
|---|---|
| 原文标题、期刊与年份 | 从原文或权威记录核对，原题保持准确 |
| DOI / 原文入口 | 使用可用链接 |
| 研究对象与类型 | 概括实际模型、队列与研究设计 |
| 材料范围 | 正文、Methods、图像/图注、已有补充文件各自的读取状态；无补充文件时说明本次以正文为范围 |
| 定位约定 | 例如“PDF 页指文件第几页；印刷页另标”，HTML 则用小标题与图号 |
| 模式、语言、来源版本 | 用户请求或默认选择；区分文件可得、已读、图像核查及未执行动作；版本标识供证据记录复用 |

将样本数放在最有帮助的位置；多队列、多模态论文可增加简短设计表，区分个体、组织、细胞和分析点数量及配对关系。

使用提取文本时注明工具及影响解读的抽取限制，保留原 PDF 定位，不要求额外制作 Markdown 底稿。补充材料不存在于本次输入范围时，不为格式完整强行补取，也不把它写成作者未提供验证。

## 研究概述

先写 Introduction 的“已有认识→未解问题→本文切入点”，再写“研究对象/总体设计→主要发现→作者提出的解释”。

既有路线仅按原文实际讨论归纳；作者认为存在的缺口与外部核验的领域结论分开。没有系统检索时不宣称穷尽历史、首次发现或当下最优。

## 全文逻辑路线图

用简洁箭头链或编号串联实际证据步骤，每步标注 Figure/表格/小标题。节点尽量说明“用何种证据回答哪一个问题”。从路线图能看出候选如何收敛、证据如何升级，或何处尚缺验证。

如正文 Results 顺序与图号不同，附一个简短对应表。不要强套“空间→单细胞→通讯→动物”或要求所有论文都有某一步。

## 逐图／逐结果精读

### Figure X｜与证据强度相称的短标题

**研究目标与动机**

说明要解决的具体问题、为什么在此处开展、与前一结果的关系。区分作者明确动机与分析者对结构的解释。

**方法与目的**

| 材料/分析对象 | 设计与比较 | 方法 | 回答的问题 |
|---|---|---|---|
| 具体样本及必要的 n | 分组、对照或分析范围 | 方法名及关键作用 | 为什么需要此方法 |

**实验设计与关键结果**

以面板或逻辑证据组组织短段落。写明比较、设计、方向、关键效应量/统计结果及位置。对于复杂分析，先解释读图需要的变量或定义。样本不足、阴性结果、不显著与作者主张的关系不能隐去。

方法表已有的内容不再逐字复述；结果已经清楚时，无需再加重复的“关键发现”清单。

**逻辑解读**

说明本图新增了什么认识，如何支持前述主张，为什么下一步要进一步定位、筛选、验证或排除解释。可用短箭头链，但不得把相关箭头写成已证实因果。

**证据边界**

针对本图给出直接支持、部分支持或仍需验证的具体判断；说明关键替代解释或假设。批评需有位置和理由，资料缺失则标无法核查，不重复无差别的通用免责声明。

**原图与来源定位**

插入实际获取、查看过的图像或已核实的官方图链接。写清图号、面板、相关 Results/Methods 小标题及可靠页码。简要区分整图概览与重点核查的面板，不必在正文逐条展示内部检查记录。只读到图注、图像分辨率不足或补图未获取时明确说明。避免伪造精确页码或不存在的图链接。

## 核心证据记录

将已有证据索引中的核心结论、可引用数字和主要批评展示为紧凑表，参照 [证据规则](evidence-rules.md#把证据索引落实到输出)。它可以放在相关图组或总结内，不必新增独立长章节。正文用证据编号或共享位置回指，避免重复每个字段。

每项保留来源版本／页码／图号／面板、比较、样本与分母／统计单位、实际核查方式、冲突和支持边界。不要用一句“所有数字已核实”替代表。多队列或数据复用论文按需加入样本层级／数据集映射；机制论文逐边区分证据，并让实验建议对应未验证环节，详见 [研究检查点](study-checks.md)。

## 研究总结与课题借鉴

按需要组织以下内容，保持简短且具体：

- **核心模型与贡献：** 哪些认识被增加，证据支持到哪里；必要时用小型“结论—关键证据—支持范围”表串联跨图论点。
- **主要局限：** 优先列真正影响核心解释或迁移的限制；区别作者自述和本次评价。
- **值得迁移的研究设计：** 指出具体环节、迁移所需材料/假设、适用条件及需要重新验证的部分。
- **延伸方向（本次提出，尚未验证）：** 从已识别缺口出发，给假设、关键对照/验证、主要判定指标、必要资源前提及合理备选路径。数量由证据决定。
- **阅读与引用建议：** 最值得回看的图/方法及其理由；说明哪些结论适合用于背景、方法或讨论，不把分析者建议当作可直接引用的论文发现。

不必再次输出与开篇相同的评分卡，也不默认生成完整申请书或词句集。叙事结构的借鉴可随设计建议简述。

## 数据与复现入口

| 资源 | 用途 | 编号/链接 | 获取状态与复现要点 |
|---|---|---|---|
| 数据/代码/补充文件 | 本文新生成、复用参考或分析实现 | 原文明确列出的入口 | 区分“原文声明”“本地未提供”“已获取未读取”“已读取的具体范围” |

代码中用了某软件不等于公开了本文分析代码。数据库编号不等于处理后矩阵、样本标签与全流程都已可得。不自动下载大型原始数据；说明最关键的复现缺口即可。

## 速读与专题的紧凑结构

- 速读：问题／筛选判断 → 真正已读与未读范围 → 决定性结果、对照与风险 → 核心证据记录 → 优先回看的图／方法与资源状态。筛选判断可为暂定，不声称全文核验。
- 专题：目标及必要上下文 → 方法／面板与关键对照 → 结果、边界与证据记录 → 缺口对应的验证或适配建议 → 本次范围与资源状态。没有必要不展开其他图与领域历史。

信息简单的完整精读也可合并导读、背景及总结，或把样本设计表并入证据记录；合并后保留必要解释、来源和不确定性。双语可以按小节相邻组织，共用证据记录并检查两种语言判断一致。
