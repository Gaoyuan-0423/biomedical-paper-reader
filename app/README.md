# BioReader App — 本地文献精读 + 图库 + 笔记 + 公众号导出

基于 [biomedical-paper-reader](../SKILL.md) skill 方法论打造的本地单用户文献阅读应用。
功能思路融合了作者的另外两个项目：**ReadBox**（几何解析取图、读图模型、证据溯源、长文预算、错误分类）与 **CiteBox**（DOI 导入、Semantic Scholar 相关文献、标签）；阅读布局和上下文问答交互参考作者的 **BohrReader**，按 BioReader 现有结构独立实现。

PDF 导入 → 双栏阅读 → 图片自动提取 → 精读/速读双模式笔记 → 图库插图 → Markdown / Word / 公众号导出。

源码网页版零构建步骤：后端 FastAPI + 前端原生 JS（pdf.js / marked / highlight.js / docx 随应用提供），`./app/run.sh` 即用。

桌面版使用 Go + [MyGo](https://github.com/egoist/mygo) 承载同一界面，Python 阅读服务和 PDF 依赖随包提供，无需用户安装 Python。DMG／Windows EXE 安装与构建见[桌面说明](DESKTOP.md)。

## 快速开始

桌面用户可直接下载 [v0.10.0 macOS / Windows 预览包](https://github.com/Gaoyuan-0423/biomedical-paper-reader/releases/tag/v0.10.0)：Apple 芯片 Mac 打开 DMG，将 `BioReader.app` 拖入应用程序；Windows 10 / 11 x64 使用安装 EXE，或完整解压便携 ZIP 后打开 `BioReader.exe`，不要单独移动 exe。Windows 需安装 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)。安装、更新、数据位置与构建步骤见[桌面版说明](DESKTOP.md)；两平台按相同版本更新，文献库仍各自保存在本机。

以下为源码启动方式：

```bash
./app/run.sh          # 默认 http://127.0.0.1:8765，可用 PORT=9000 ./app/run.sh 改端口
```

Python 依赖见 `backend/requirements.txt`（fastapi、uvicorn、pypdf、httpx、python-multipart、
pdfplumber、pypdfium2、Pillow）。

## 阅读工作台

- 顶部「专注原文」展开 PDF 并收起其他面板；「笔记对照」并排阅读原文与笔记；「边读边问」打开原文旁的问答。切换布局保留笔记草稿和当前阅读页。
- 桌面默认并排展示文献库、论文原文和阅读笔记；原文标题旁可收起文献库，分隔条可拖动或用左右方向键调整。正文和补充 PDF 保留连续滚动、缩放与各自的阅读位置。
- 窗口宽度不超过 900px 时，使用顶部「文献库 / 论文原文 / 阅读笔记」切换，避免三栏挤压。
- 所有界面图标使用内置 SVG，无额外图标库或构建依赖。`⌘/Ctrl+K` 聚焦文献搜索。
- 「笔记 / 编辑 / 图库 / 问答」切换内容；笔记右上角显示保存状态，`⌘/Ctrl+S` 立即保存。
- 论文标题下的期刊与年份可展开完整作者、DOI 等信息；导出操作统一收在「导出」菜单。
- 读图追问与图注编辑使用弹窗；留空追问表示整体观察，取消或 Esc 不发起读图。
- 设置中的模型连接与研究方向常显；生成上限和相关文献 API Key 收在「高级设置」。

## 原文引用与章节导航

原文工具栏下方的“阅读导航”默认收起，展开后可查看“章节／图表／笔记”：

- 章节采用当前 PDF 自带书签并解析实际页码；没有书签或目标不可解析时明确显示，外部动作不会执行。
- 图表只显示当前正文或补充文件中已提取的图片；点击后定位 PDF 页面，并滚动笔记中的对应图片。没有可确定的笔记位置时只定位原图并提示，不猜测补图对应章节。
- 笔记目录采用当前 Markdown 标题，重复标题各自保留独立位置。切换论文或材料时，旧目录请求不能覆盖新视图。

新生成的完整精读可包含“原文 · 页码”按钮。每条来源保存实际原文摘录、文件、页码、文件哈希和可用的几何坐标；点击时先保存当前笔记，再校验来源。人工编辑可保留已有链接，删除链接后不可继续解析该引用；正文或补充文件被替换／移除时，旧摘录保留，跳转禁用。

旧笔记、普通参考文献编号、代码示例和未匹配来源保持原样。速读继续使用原有简洁输出。长文概览只是线索，系统会在预算内重新附上实际原文块，只有这些片段可生成来源按钮；不会把有出处等同于科学结论已获验证。部分生成结果保留快照，保存成功后仍可回跳；生成期间的人工修改不会被旧输出覆盖。

Markdown、Word 和公众号导出使用可读的文件名、PDF 页码与摘录，不要求接收者安装 BioReader。原文来源快照保存在每篇论文的 `note-sources/` 中。

笔记预览和公众号使用安全 Markdown 排版，支持标题、列表、表格、代码与本地图像。原始 HTML 显示为文字，内部注释隐藏，不加载远程图片或执行危险链接。

## 搜索正文与笔记

侧栏「搜索正文与笔记」用于检索本机文献库。输入至少两个字符的关键词或原文短语，可选择「正文与笔记」「仅正文与补充」或「仅已保存笔记」。它不受侧栏星标或标签筛选影响；标题／作者搜索仍由原来的文献列表搜索框完成。

- **实际保存内容**：搜索正文和补充 PDF 的文本层，以及已保存的阅读笔记；未保存草稿、独立问答历史和 GEO 缓存不在范围内。按归一化的连续关键词／短语匹配，不是语义检索或跨论文 AI 问答。
- **结果与分页**：结果显示论文标题、真实命中片段，以及 PDF 文件名和页码或「已保存笔记」。每次加载 20 条，可点「加载更多」；修改条件后重新搜索，旧条件的迟到结果不会覆盖新结果。
- **PDF 来源**：点击结果时重新校验文件版本，再打开对应正文／补充文件的 PDF 页。有可靠坐标时短暂高亮对应区域，没有坐标时只跳页。来源被替换或删除时提示重新搜索，不跳到旧来源。
- **笔记来源**：点击笔记结果会打开该论文的已保存笔记；目前不定位或高亮笔记中的具体句子。笔记发生变化时需要重新搜索。切换仍遵循现有草稿与生成任务保护。
- **本地读取与限制**：搜索不联网、不调用模型。旧 PDF 首次读取时会提取并缓存文本，耗时取决于文献数量和页数；不可读取的文件会在结果中提示。扫描件没有文本层时不能搜索，本版不做 OCR。

## 连接 Zotero MCP

v0.7.0 的首批连接器针对 [54yyyu/zotero-mcp](https://github.com/54yyyu/zotero-mcp) 的 **Streamable HTTP** 接口，支持该传输返回的 JSON 和 SSE 响应。它不是所有同名 Zotero MCP 服务的通用适配器，也不使用 `stdio` 或旧式独立 `/sse` 传输。连接时检查 `zotero_search_items`、`zotero_get_item_metadata` 和 `zotero_get_item_children`；元数据工具需支持 `format="json"`。

### 先保存连接设置

在右上角设置中的 Zotero MCP 区填写：

| 设置 | 默认值与用途 |
|---|---|
| MCP 地址 | `http://127.0.0.1:8000/mcp`，指向已运行的服务 |
| Bearer Token（可选） | 仅当你的 MCP 服务或代理要求此鉴权时填写；上游默认本地服务无需此值，不能把 Zotero Web API Key 当作它 |
| 本机存储目录 | `~/Zotero/storage`，对应 Zotero 数据目录下的 `storage` 文件夹；自定义数据目录时需调整 |

`localhost` 和 `127.0.0.1` 都指运行 BioReader 的使用者自己的电脑。不同用户可以填写相同的本机地址，各自连接各自的服务；GitHub 发布包不会连接开发者的 Zotero。默认附件目录在运行时按当前用户的主目录生成，连接配置和凭据也分别保存在各自的本机数据目录中。

注意区分：`http://localhost:23119/api/` 是 **Zotero 自带的本地 API**；这里填写的是另行启动的 **MCP 服务地址**，例如 `http://127.0.0.1:8000/mcp`。勾选 Zotero 的「允许通讯」是启用前者，并不会自动启动 MCP。详情见 [Zotero 本地 API 文档](https://www.zotero.org/support/dev/web_api/v3/local_api)。

还没有安装 Zotero MCP 时可以先保存这些设置，稍后再测试连接。BioReader 不安装、不启动服务，也不修改 Zotero 或其他客户端的配置。Zotero 连接及 Token 单独保存在 BioReader 数据目录的 `zotero.json` 中，Token 以明文存储且不回显；模型配置仍使用 `settings.json`，两者独立保存。导入文献不需要模型 API Key。

### 安装并启动官方服务

准备 Python 3.10+ 和 Zotero 7+，在 Zotero 的「设置 → 高级」打开「允许此计算机上的其他应用程序与 Zotero 通信」。按[官方安装指南](https://github.com/54yyyu/zotero-mcp/blob/main/docs/getting-started.md)安装服务；已安装 `uv` 时可运行：

```bash
uv tool install zotero-mcp-server
ZOTERO_LOCAL=true zotero-mcp serve --transport streamable-http --host 127.0.0.1 --port 8000
```

没有 `uv` 时可采用官方列出的 `pipx install zotero-mcp-server` 或 Python 环境中的 `pip install zotero-mcp-server`，启动命令相同。保持服务运行，再回到 BioReader 测试连接。上述本地只读用法不要求 Zotero Web API Key，也不用运行写入授权或 Claude 配置命令。额外语义检索／读 PDF 插件不是本连接器的必需项。参数与 `/mcp` 路径依据[上游 CLI](https://github.com/54yyyu/zotero-mcp/blob/main/src/zotero_mcp/cli.py)及安装指南；上游版本变更时以其文档为准。

### 检索、预览与导入

1. 打开「Zotero」入口，按短关键词、作者或标题检索当前服务的活动文库。预览后确认文献身份和附件；首版不在 BioReader 中切换 Zotero 文库。
2. 明确选择「仅导入元数据」，或选择一份可用的本机存储 PDF 作为正文导入。元数据包括文献标题、作者、期刊、日期、DOI、摘要和标签等；不会自动生成笔记或复制 Zotero 中的笔记。
3. 以 Zotero 来源文库／条目 Key 和 DOI 查重。命中 BioReader 已有记录时返回该记录，可点击「打开文献」继续阅读；保留已有正文、笔记及人工修改，重复导入不会自动替换或补入 PDF。

PDF 导入只支持配置目录中已经存在的 Zotero 存储附件（`imported_file`、`imported_url`），读取范围为 `storage/<附件 Key>/<文件名>`，并核对附件所属论文、类型和文件内容。链接文件 `linked_file`、网址附件 `linked_url`、尚未下载的云端文件和另一台机器上的路径不能通过此入口读取；可先在 Zotero 下载到本机存储，或使用 BioReader 原有 PDF 上传入口。缺少 PDF 时仍可明确选择仅导入元数据，不会把全文摘要或抽取文本伪装成 PDF。

上游的附件路径工具返回的是服务器文件路径，而不是 PDF 字节；Zotero [本地 API](https://www.zotero.org/support/dev/web_api/v3/local_api)的 `/file` 也返回 `file://` 重定向。BioReader 因而不读取 MCP 返回的任意路径或自动追随附件 URL。首版只允许本机回环地址上的 MCP 导入配置目录中的 PDF；远端 MCP 仅支持元数据导入，不能用远端路径或本机同名文件冒充附件。首次连接不自动遍历或导入整库，导入过程不向 Zotero 写回任何数据。

连接失败时先确认服务仍在运行、地址包含 `/mcp`、传输选择 `streamable-http`，以及服务器版本提供上述三个工具和 JSON 元数据；附件不可用时检查本机目录及 Zotero 下载状态。不要把 HTTP 连接成功等同于 PDF 文件已在本机。

## 原文选字与问答

在 PDF 中拖选文字后，点击「解释」「翻译」或「追问」；也可以直接打开「问答」标签页输入问题。选区会保留其所属文件和 PDF 页码，滚动到别页不会改变已选问题的来源。取图模式下拖动仍用于裁图，退出取图后恢复文字选择。

- **按论文保存**：问题与回答独立保存在当前论文的 `chat.json`，重新打开会恢复；较早内容通过「加载更早对话」读取，不覆盖精读笔记。输入草稿按论文暂存于当前窗口会话，尚未提交的草稿不等于已写入文献库。
- **结合原文回答**：在本篇正文和补充 PDF 中本地选择相关文本片段，结合当前文件、页码和选区发给已配置的文本模型。不是整库语义检索，也不保证每次问题覆盖全文；扫描 PDF 没有可提取文字时会提示材料不足。
- **排版与快捷问题**：已完成回答按 Markdown 显示标题、列表、表格和代码块，回答中的 HTML 不会执行，远端图片不加载。快捷问题针对当前页或选区，点击只填入问题，可修改后手动发送；不会清空已有问题草稿，不代表已读取全文。
- **复制与追加笔记**：已完成回答可复制为 Markdown，也可连同来源文件、PDF 页码和原文摘录追加到现有笔记。追加前先保存已有编辑，始终保留原内容；同一回答重复点击不会再追加，保存失败时保留草稿并可重试。追加内容沿用回答当时的来源快照，不自动认证科学结论；未完成回答不能作为完整摘录追加。
- **查看引用**：回答中的有效来源按钮先核对文件版本，再跳到相应正文／补充 PDF 的页码；保存了真实文本块位置时短暂高亮对应区域，没有坐标时只定位页面。源文件被替换或删除后保留旧回答并提示引用不可用，不跳到错误材料。
- **停止与恢复**：回答逐段出现，可停止。超时、断流、输出截断和模型错误不会显示为完整回答，已生成部分仍保留，可以重新提问。切换文献会自动停止旧回答，输入草稿仍按论文暂存。
- **范围**：问答使用现有模型设置，需要 API Key；读取历史、选择文字和跳转来源本身不调用模型。问答历史不会自动并入笔记导出；手动追加的摘录成为笔记的一部分，可随笔记导出。不自动确认科学结论或证据卡片，也不执行自主工具任务。

## 星标、标签与证据

通过星标收藏重点文献，搜索和标签可以组合筛选。「清除筛选」恢复全部文献。侧栏不再显示「筛选与待办」、待办数量或文献待办徽标，资源入口仍位于文献列表下方。

- **简化阅读管理**：移除阅读进度、阅读决策及「判断阅读价值」按钮。旧版保存的字段保持兼容，但不再影响显示或待办。
- **相关页面提醒**：缺少正文、笔记未完成、材料变化、证据核查和记录读取问题仍在所属文献页面显示。数据与复现资源不再需要核对状态或待办步骤。
- **笔记完整性**：生成中断且已有输出时保留部分笔记及未完成标记，普通编辑不会清除该标记。手动补完后点击「已手动补完笔记」，或成功重新生成。
- **材料变化**：增加或移除补充 PDF、替换正文后，已有笔记会提示核对新材料；可以核对后点击「已核对新材料」，或重新生成。仅编辑笔记、自动配图不会自动解除提醒；生成期间发生的材料变化也会保留提醒。
- **关键证据**：「证据」标签页添加待核查判断、原文摘录或图表观察，选择来源文件、PDF 页码和可选的图表。笔记里选中文字后点「记证据」，会将它带入判断栏；摘录和来源由你补充核实。证据状态分为待核查、已核查、不支持该判断。
- **回到原文**：证据卡片跳转到所选文件的 PDF 页码；笔记中已有图片也显示「查看原文」入口。页码指 PDF 文件内页序号。源文件替换后已核查证据重新待核查；源文件移除后保留证据文本并明确提示来源不可用。
- **保存保护**：证据草稿或保存请求未完成时阻止切换文献和修改材料；可切换到原文核对，再回到证据页保存或取消。保存失败保留输入，不把失败显示为成功。

证据独立保存在每篇文献的 `evidence.json`。证据为人工整理，不自动从报告推断原文引文，也不会由 AI 自动确认。Markdown／Word／公众号导出会附上已保存的证据与资源记录，证据保留待核查、驳回等状态，资源只显示内容与来源情况。

## 数据与复现

资源页使用整个阅读工作区，按「资源、用途、编号／链接、影响使用的条件、样品／材料」展示；回到笔记或查看原文时恢复阅读布局。优先保留精读中「数据与复现入口」表格的分组：一行可包含多个队列编号，细胞系和命名资源也能保存。通过「当前论文／全部文献」切换范围，并可检索用途、编号、样品和条件。

- **从精读笔记整理**：完整且材料未过期的精读成功保存后，自动整理资源表。已有精读可点「从精读笔记整理」，不必重新生成。优先读取资源表格；没有匹配表格时，才提取明确的数据库编号或支持的代码／数据仓库链接。不再把整段 Markdown 笔记片段重复塞入资源卡片。
- **样品／材料**：保留原始样品说明，并分别保存物种／研究对象、组织／部位、疾病／状态、技术类型、平台、论文实验分组和论文实际样本量。样本量可写「肿瘤 8 例；正常 5 例」，保留单位与队列对应关系；不把不同队列加总，不把数据库总量填作论文用量。多个队列仍可保留在同一资源行。
- **结构字段整理**：新版 App 精读模板提示使用「物种：…；组织：…；疾病：…；分组：…；样本量：…；技术：…；平台：…」标签。整理器接受明确标签或独立表格列，不从含糊叙述猜测字段；未报告和冲突信息保留在原始说明中，不推断填值。旧笔记没有明确标签时可直接编辑补充，保存后不再被自动整理覆盖。
- **组合筛选**：展开「按样品信息筛选」，填写物种、组织、疾病、技术和平台关键词。多个条件同时满足才显示，空白条件不参与；关键词按归一化、忽略大小写的子串匹配。点击「搜索」或「应用筛选」更新结果，支持「当前论文」与「全部论文」；尚未应用的条件不能直接用于导出。
- **补充 GEO 信息**：GSE 编号提供手动查询按钮，从 [NCBI GEO 公开元数据](https://www.ncbi.nlm.nih.gov/geo/info/download.html)补充研究设计、检测类型、平台及至多 3 个样品示例（物种、来源、特征和建库方式）。GEO 收录总数与论文实际使用量分开显示；示例不代表全部样品或所有分组。每个 GSE／GSM 附原始链接，查询不需要模型 API Key，也不下载表达矩阵。
- **独立缓存**：打开页面只读取本地 GEO 缓存；点击按钮才联网，完整结果缓存 7 天，可手动刷新。失败保留已有结果及人工记录。公开元数据保存在 `geo_metadata.json`，不改写论文的用途或样品明细，当前不纳入报告导出。
- **兼容旧记录**：旧数据读取时为新增字段提供空值，不重写原文件。重新整理时，能够确认未被人工改动的自动记录可转换成分组表格或补齐明确样品字段；替换前保存完整 `resources.backup-*.json`，兼容旧自动记录指纹。人工修改和旧版已核对的记录保留，重复整理不追加同一行；历史状态只作兼容，不再显示。
- **直接编辑与保存**：编辑资源名称、用途、完整编号／链接、使用条件及样品明细后点击「保存资源」即可。资源表、详情和导出不再显示待核对／已核对标签，也无需另行确认状态。补充信息中保留类型、仓库、与本文关系、备注和可选 PDF 页码，来源文件变化或失效仍提示。
- **跨论文关联**：按明确编号或资源 URL 关联，组合行中的每个编号均可匹配。共同仓库名称、细胞系名称或「未报告」等文字不会触发关联。
- **草稿保护**：保存失败保留输入，未保存草稿会阻止切换论文、修改材料或导出。全库只查看与跳转，编辑在所属论文中完成。
- **报告导出**：Markdown ZIP、Word 与公众号内容统一附上已保存的证据、资源用途、编号／链接、使用条件、原始样品说明、结构字段和原文来源；证据继续保留核查状态，资源不再附状态。人工备注保留，旧自动笔记片段不再重复输出；不修改编辑器笔记。
- **资源表 CSV／编号清单**：「导出当前结果」遵循已应用的查询、样品条件和当前论文／全库范围。CSV 每行对应一条论文资源，含论文标题、DOI／ID、7 个样品字段、原文页码与出处；采用 UTF-8 BOM、CRLF 和公式前缀保护，便于电子表格读取。编号 TXT 只包含明确支持的仓库编号，排序去重；不从用途或备注推断编号，命名队列和代码网址不会伪装成 accession。没有可识别编号时清单为空；GEO 缓存与资源核对状态均不进入这些文件。

资源保存在 `resources.json`。精读资源整理在本地完成，不额外调用模型；只有明确点击 GEO 补充按钮才查询远端。外部链接只接受 HTTP(S)，PDF 页码按文件页序号计算。

## 配置 API（右上角 设置）

| 字段 | 说明 |
|---|---|
| Base URL / API Key | 任意 OpenAI 兼容接口（BigModel / DeepSeek / OpenAI…），不允许 localhost / 内网地址 |
| 文本模型 | 写笔记、长文分段整理、主题标签识别和原文问答用 |
| 读图模型（可选） | 填视觉模型（如 `glm-4.6v`）后，生成精读笔记前会先让模型逐张观察主图，观察结果随图注一起进入提示词；图库中「读图 / 全部读图」可单独触发 |
| 送入模型的最大字符数 | 超出时**不再粗暴截断**：自动按页分段整理成带页码的要点笔记（并发压缩、进度可见），再写报告 |
| 单次输出上限 | 0 = 接口默认；精读报告较长，建议 16384+ |
| 最多读图张数 | 按页码顺序取前 N 张主图送视觉模型 |
| Semantic Scholar Key（可选） | 相关文献检索用；匿名额度较慢，可免费申请 |
| 我的研究方向（可选） | 写入提示词，让「过滤结论 / 决策卡」按你的方向判断相关度 |

## 功能

### 文献库
- **正文 + 补充 PDF**：先导入正文，再在该文献的阅读器中点击「添加补充 PDF」（支持多份）。下拉框在各文件间切换，页码分别计算；生成笔记联合读取正文、补充方法和补图，并保留文件来源。添加材料不会自动改写旧笔记，需重新生成以更新分析。重复文件会提示，错误文件不会替换正文。
- **继续阅读**：每篇文献记住最近打开的正文／补充文件，各文件独立保存页码、缩放和适宽设置。切换文件或重新打开 App 后，再打开文献即可恢复；位置保存在本地文献目录，不依赖浏览器端口，也不会改写笔记。
- **长 PDF**：只渲染可见页及相邻页，滚远后释放画布；跳页优先显示目标页，单页加载失败可点击重试。横竖版混排按最宽页适宽；手动放大仍可横向滚动。图库卡片的「查看原文」自动切换到对应文件和页码。
- **导入 PDF**：点击或拖拽（≤80MB）；几何解析器自动产出**双栏正确阅读顺序**的全文（含章节标题识别），
  并按图注锚定**提取全部主图与子图**（图注合并整理、期刊页眉页脚过滤、面板字母切分）。
- **DOI 导入**：贴 DOI / doi.org 链接 → CrossRef 拉取标题、作者、期刊、年份、摘要建条目 →
  中间面板「附加 PDF」补文件（附加不会覆盖 CrossRef 元数据）。
- **元数据补全**：文献标题旁「补全文献信息」按钮用 CrossRef 补作者/年份/期刊（已有字段不覆盖）。
- **收藏 / 搜索 / 标签**：精读／速读笔记成功保存后自动识别主题标签；已有文献可在标题下点击「识别标签」补全，无需重写笔记。也可回车手动添加、点 × 移除，侧栏标签常显并可直接筛选。自动识别使用当前文本模型，增加一次简短请求；未配置 API Key 时可继续手动管理。每次识别最多等待60秒，超时、临时网络／限流或无效格式会自动重试一次。识别只补充标签，不删除已有标签；失败可重试，不影响已保存笔记。

### 阅读与图片（取图思路来自 skill 的问题驱动核查）
- 左侧 pdf.js 渲染（翻页/缩放/适宽/分隔条）。
- **图库标签页**：全部图片卡片（缩略图/图注/页码/来源），点缩略图放大，
  「图注」「删除图片」「插入笔记」；「重新提取」保留手动图与已有读图观察（ReadBox 合并规则）。
- **手动取图**：PDF 工具栏进入取图模式，在页面上拖框截取任意区域（矢量图、扫描件、跨页图的兜底），
  手动裁图以 3 倍分辨率渲染，保证面板标签与统计标注可读。
- **读图（问题驱动）**：任何一张图（含刚裁的）都可以立刻让读图模型观察，
  并可带具体追问（如「F 面板两组的差别和显著性？」）；配置了读图模型时，裁图完成后自动弹出追问。
  观察结果缓存在卡片上，随图注一起进入笔记生成材料。

### 笔记生成（SSE 流式）
- **完整精读**：skill 报告模板（开篇导读 → 逐图精读 → 课题借鉴 → 复现入口）。
- **速读筛选**：一分钟判断值不值得精读。
- 引用遵循 skill 的自然引用原则：图号／面板／小节定位（如「Fig. 3B–D 展示……」），不逐句标页码；图片清单（图注 + 视觉观察）随提示词注入。
- 手动笔记按顺序自动保存；保存失败时内容保留在编辑器中，可按 ⌘/Ctrl+S 重试，保存完成后再切换文献。
- 生成中显示分阶段进度（读图 x/y、长文整理 x/y），可随时停止并保留已生成部分。
- 停止或连接中断时保留并保存已生成部分，标记“未完成”；生成没有产出时保留原笔记。
- 上游错误分类为可操作建议（上下文超限/输出超限/图片被拒/模型名错/鉴权/限流），不回显原始报文。

### 相关文献（CiteBox 思路）
- 文献标题旁「相关文献」按钮 → Semantic Scholar 该文的**参考文献**与**引用本文**（按被引排序），
  逐条「导入」按钮直接按 DOI 入库；结果缓存 7 天，可强制刷新。

### 导出
- **自动配图**：新生成笔记按有效引用放图，遗漏的主图与补图自动补到对应图标题或「原文图集」；速读只配实际提到的图。旧的纯文字笔记在 Word、Markdown ZIP 和公众号导出时也会自动配图。若想在编辑器中保存配图版，使用导出菜单的「为已有笔记自动配图」（不调用 AI）。
- 自动配图只使用图库中实际存在的图片，不等于视觉核查；没有提取出图片时仍需手动取图。图片文件缺失会提示，避免悄悄导出无图版本。
- **Markdown + 图片**：默认导出 ZIP，包含 `report.md` 与 `assets/*.png`；引用使用相对路径，解压后一起移动即可显示图片。
- **Word 文档**：docx 文档（标题层级、可编辑表格、代码、图片内嵌），按需加载本地 docx 库。
- **复制到公众号**：「导出」菜单中按所选主题排版并复制（4 套主题，菜单内下拉切换），
  mdnice 同款管线（CSS 全内联、伪元素转 span、代码 `<br>`+NBSP 加固、外链转脚注）；
  笔记里 `![Figure X](figure:xxx)` 的图片自动内嵌 base64，粘贴进公众号编辑器不丢图。

## 数据位置

桌面包默认使用独立的用户数据目录：macOS 为 `~/Library/Application Support/BioReader/`，Windows 为 `%LOCALAPPDATA%\BioReader`。更新程序不会删除这些目录；`BIOREADER_DATA_DIR` 可覆盖桌面版默认位置。下列 `app/data/` 是源码服务的默认目录，不会自动迁移到桌面版，也不会跨电脑同步。

```
app/data/
├── settings.json          # 模型 API 配置
├── zotero.json            # 独立 MCP 地址、可选 Token 与本机附件目录
└── papers/<id>/           # 每篇一个目录
    ├── paper.pdf / text.txt / meta.json
    ├── supplements/<id>.pdf / <id>.txt  # 独立补充文件及文本，清单在 meta.json
    ├── reading/<document-id>.json      # 各 PDF 的阅读位置，独立原子写入
    ├── blocks/<document-id>.json       # 与源 PDF 版本绑定的原文文本块及可用坐标
    ├── evidence.json      # 关键判断、来源页码与人工核查状态
    ├── chat.json          # 本篇问题、回答、来源快照与中断状态
    ├── resources.json     # 资源用途、编号、条件、样品和原文依据
    ├── resources.backup-*.json # 升级旧自动记录前的完整备份
    ├── geo_metadata.json  # 可选的公开 GEO 元数据缓存
    ├── figures.json       # 图片清单（bbox、图注、读图观察）
    └── figures/*.png      # 裁取的图片
```

`app/data/` 已 gitignore。API Key 明文存于本地 settings.json，仅用于向你配置的接口发起请求。

出站请求包括你配置的 LLM 接口（SSRF 校验 + 重定向逐跳复检）、`api.crossref.org`、`api.semanticscholar.org`、固定的 GEO 元数据端点 `www.ncbi.nlm.nih.gov/geo/query/acc.cgi`，以及你明确配置并调用的 Zotero MCP 地址。MCP 默认连接本机 `127.0.0.1:8000`；只调用检索、元数据和附件列表工具，不执行服务器提供的任意工具或下载其返回的任意 URL。

## 已知边界

- 图注锚定取图依赖 PDF 内嵌文本/对象几何；纯扫描件走 pypdf 文本兜底 + 手动取图。
- Semantic Scholar 匿名额度有限（约 1 请求/秒，共享池），频繁使用建议填免费 API Key。
- OCR 未内置（ReadBox 有 Tesseract 管线，本应用为保持轻量暂未移植）。
- 公众号粘贴对代码块已加固；数学公式仍建议截图插入。
