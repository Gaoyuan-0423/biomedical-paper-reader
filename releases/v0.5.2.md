# v0.5.2

## 中文

BioReader 阅读操作与资源整理修复版，作为 **Pre-release** 发布。保留原有蓝白工作台、历史版本和 v0.3.4 稳定版入口。

### 本次变化

- 「判断阅读价值」打开明确的选择窗口，选择优先精读、留作参考、暂不相关或待判断并保存；不会自动改为已读。
- 自动标签每次等待上限由20秒延长到60秒；超时、临时网络故障、限流／服务暂时失败或无效标签格式可自动重试一次。缩短输入并增加回答预算，兼容明确的 JSON 标签包装。鉴权等永久错误不重试。
- 「筛选与待办」「数据与代码」移至文献列表下方；筛选向上展开，保留文献列表的滚动空间。
- 完整精读成功保存后，从笔记中明确出现的数据库编号和数据／代码仓库链接自动整理资源。已有精读可点「从精读笔记整理」，不必重新生成。
- 资源整理在本地完成，不额外调用模型或查询远端仓库。新增项全部待核查，说明来自精读笔记并保留片段；不猜填缺失链接、原文页码、物种或技术属性。已有人工和已核对记录保持不变，重复跳过。
- 速读、未完成或材料过期的笔记不自动整理资源。标签和资源后处理独立，失败保留已保存笔记，自动成功提示不会覆盖另一操作的错误。

### 下载与验证范围

下载 `BioReader-v0.5.2-macos-arm64.zip`，退出旧版后用解压出的 `BioReader.app` 替换。适用于 Apple 芯片 Mac；用户目录中的论文、笔记和设置保留。`SHA256SUMS.txt` 可用于 `shasum -a 256 -c SHA256SUMS.txt` 核对附件。

100项前端、71项App后端及仓库检查通过。真实Chrome验证中，模拟模型延迟21秒仍成功返回，第一次503后自动第二次成功。验证使用隔离合成文献与模拟模型，包含笔记保存、阅读决策、资源去重／待核查状态、并发保护、标签超时／重试及浏览器布局。没有调用真实付费模型，也不声明标签准确率、全部资源覆盖率或远端编号存在。详见[验证记录](https://github.com/Gaoyuan-0423/biomedical-paper-reader/blob/v0.5.2/app/tests/README.md)。原生 WebKit 本轮未重新验收，应用尚未进行 Apple 开发者签名或公证。

## English

This **Pre-release** fixes reading actions and adds local resource extraction from completed deep-reading notes. The blue-and-white workspace, earlier releases and stable v0.3.4 remain available.

### Changes

- The reading-value action now opens an explicit decision dialog and persists the selected decision without changing reading progress.
- Tag recognition allows 60 seconds per attempt instead of 20. Timeouts, temporary network failures, rate limits/server failures, or invalid tag formats receive one automatic retry. Inputs are shorter, the response budget is larger, and an unambiguous JSON tag wrapper is accepted. Authentication failures are not retried.
- Library filters/tasks and data/code access move beneath the paper list, with filters opening upwards.
- Successfully saved complete deep-reading notes automatically yield pending resource candidates for explicit accessions and supported repository links. Existing deep notes offer a separate extraction action.
- Extraction is local and deterministic: no additional model request or remote lookup. It preserves note excerpts and labels provenance as reading notes, never inventing missing links, PDF pages or study attributes. Existing human/verified records remain unchanged; duplicates are skipped.
- Quick, incomplete or stale notes do not trigger resource extraction. Tagging and extraction failures remain independent of saved notes and each other; automatic success messages no longer hide the other action's failure.

### Download and validation scope

Download `BioReader-v0.5.2-macos-arm64.zip` for Apple silicon Macs, quit the older app and replace it with the extracted `BioReader.app`. Existing papers, notes and settings in the user directory are retained. Verify the accompanying checksum file using `shasum -a 256 -c SHA256SUMS.txt`.

All 100 frontend and 71 app backend tests and repository checks passed. Real Chrome tests confirmed a simulated 21-second tag response succeeds and a first HTTP 503 receives one successful retry. Validation uses isolated synthetic papers and mocked model responses for saved notes, decisions, resource deduplication/pending status, concurrency, tag timeout/retry and browser layouts. No live paid model was called; no tagging-accuracy, exhaustive-extraction or remote-accession-validity claim is made. See the [validation record](https://github.com/Gaoyuan-0423/biomedical-paper-reader/blob/v0.5.2/app/tests/README.md). Native WebKit was not rechecked; the app has no Apple Developer ID signature or notarization.
