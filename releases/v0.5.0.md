# v0.5.0

## 中文

BioReader 研究工作台预览版：蓝白界面、阅读进度与待办、关键证据、数据与代码整理，以及统一的报告导出。此版本基于 v0.4.0 之后的源码更新，作为 **Pre-release** 发布；v0.3.4 稳定版保持不变。论文精读方法与证据标准没有改动。

### 下载与安装

1. 下载本页附件 `BioReader-v0.5.0-macos-arm64.zip`，适用于 Apple 芯片 Mac（arm64）。
2. 退出旧版，解压后打开 `BioReader.app`，或拖入“应用程序”。不需另装 Python 或手动启动终端。替换应用不会删除用户目录中的已有文献、笔记和设置。
3. 可同时下载 `SHA256SUMS.txt`，在同一目录运行 `shasum -a 256 -c SHA256SUMS.txt` 核对完整性。

### 主要变化

- 蓝白色阅读工作台：统一按钮、卡片和状态颜色，增强辅助文字对比度，收紧标题区与工具栏；筛选与待办按需展开，收起后仍显示筛选数量。
- 阅读进度与阅读决策分别由人标记；AI 报告生成不会把文献自动标为已读。缺全文、精读中、生成未完成、材料变化及待核查记录会形成可点击的待办。
- 关键证据记录判断、摘录、正文／补充 PDF 页码和人工核查结果。从证据或笔记图片可以回到原文；材料变化会让旧的已核查记录重新待核查。
- 数据与代码记录仓库编号、链接、研究对象、技术与本文关系；支持全库搜索和共享编号的关联论文。新产生、复用和方法实现等角色按每篇论文分别保留。
- Markdown ZIP、Word 和公众号内容统一附上已保存的证据与资源，包括待核查、驳回、来源失效等状态。Word 资源链接可点击，报告不改写原笔记；只有资源、没有笔记的条目也能导出。
- 包含 v0.4.0 后的阅读改进：独立补充材料、自动配图、长 PDF 按需渲染、正文／补充阅读位置恢复、保存和生成中断保护。
- 证据或资源文件损坏时隔离错误，文献库仍可使用并显示提示；不会将损坏文件静默覆盖或导出成完整报告。

### 验证与限制

- 前端 69 项、App 后端 46 项、阅读记录 15 项、发布元数据 10 项及完整性自测 4 项全部通过，版本与仓库完整性检查通过。真实 Chrome 的两组检查共 20 个场景通过，在隔离合成文献库中验证状态持久化、筛选、证据与资源 CRUD、跨文件／跨论文跳转、草稿保护、桌面与窄窗口布局；实际 ZIP 和 DOCX 已检查附录、图片、中文和超链接。
- 本地 arm64 应用构建、包完整性、随包源码一致性和 ZIP 解压检查通过。检查不等于 Apple 开发者签名或公证；首次打开可能被 macOS 拦截。本轮新界面未另行复验原生 WebKit 窗口或其他 Mac 型号。
- 没有调用真实付费模型，也未重新评测真实论文科学解读质量。资源由人工整理，未实现自动编号提取、远程仓库检索或研究数据下载；公众号目标编辑器粘贴未实测。

## English

BioReader research-workbench preview adds a blue-and-white interface, reading progress and tasks, evidence cards, data/code resources, and unified report exports. It includes source changes since v0.4.0 and is published as a **Pre-release**; stable v0.3.4 remains unchanged. Scientific reading methodology and evidence standards are unchanged.

### Download and install

Download `BioReader-v0.5.0-macos-arm64.zip` for Apple silicon Macs. Quit an older instance, extract the ZIP, and open `BioReader.app` or move it to Applications. No separate Python installation or terminal startup is required. Replacing the app does not delete existing papers, notes, or settings in the user data directory. Optionally download `SHA256SUMS.txt` and run `shasum -a 256 -c SHA256SUMS.txt` beside the ZIP.

### Changes

- Consistent blue-and-white surfaces, clearer secondary text, compact headings/toolbars, and collapsible library filters with visible active-filter counts.
- Separate human reading progress and relevance decisions; generating an AI report never marks a paper as read. Derived tasks cover missing PDFs, unfinished reading/notes, changed materials, and records awaiting verification.
- Evidence cards retain claims, excerpts, source documents/pages, and human decisions. Cards and note images navigate to the source PDF; changed materials reopen verification.
- Data/code records retain repository IDs, links, study metadata, and per-paper generated/reused/implementation roles. Local cross-paper search identifies shared resource records.
- Markdown ZIP, Word, and WeChat exports append saved evidence/resources without rewriting notes, preserving pending/rejected/source-unavailable states. Word links are clickable; resources can be exported without a main note.
- Includes post-v0.4.0 supplementary-PDF support, automatic note figures, on-demand long-PDF rendering, per-document reading-position restoration, and save/interruption protections.
- Invalid evidence/resource sidecars are isolated with explicit warnings. The library remains accessible, and damaged files are never silently replaced or exported as complete records.

### Validation and limits

All 69 frontend, 46 app backend, 15 reading-record, 10 release-metadata, and 4 integrity self-tests passed, along with version and repository integrity checks. Two real Chrome suites passed all 20 scenarios, using isolated synthetic papers to exercise persistence, filters, evidence/resources, source navigation, draft protection, and desktop/narrow layouts. Downloaded ZIP and DOCX files were inspected for appendices, images, Chinese text, and hyperlinks.

The arm64 bundle passed build, local integrity, bundled-source consistency, and ZIP extraction checks. It has no Apple Developer ID signature or notarization; macOS may block first launch. The new interface was not separately rechecked in the native WebKit window or on other Mac models. No live paid model or new real-paper scientific-quality evaluation was run. Resources are manually curated; automatic accession extraction, remote repository search, and research-data downloads are not implemented. Pasting into the external WeChat editor was not tested.
