# v0.16.0 工程验收

本版涉及跨篇比较、报告结论复核、报告生成时的读图记录、三处阅读快捷操作、PubMed 补查、组会 PPTX 和本机 Zotero 迁移。全库检索用生成的 PDF 对照原实现、标准库优化与 Rust 原型的完整请求。[App 验证记录](../../../app/tests/README.md) · [基准复跑方法](../../benchmarks/README.md)

本轮记录工程行为及响应时间。研究者真实核对耗时、候选值修改率和引文对科学结论的支持程度尚待实读评测。阅读规则文件的哈希记录在 [manifest.json](manifest.json)。

### 五篇论文的比较草稿

原创合成材料中的四篇有正文和补充 PDF，一篇仅有正文。预先写下每篇论文的入组人数、完整配对人数、实际进入单细胞分析的人数和取样部位，再检查草稿中的候选值、引文、文档和页码。按「论文 × 字段」核算，20 项中有 17 项具备已保存的直接依据，17 项均给出与预期一致的候选及出处。其余 3 项缺少相应摘录，保持空白。另一个回归用例专门检查原句明确指向缺失补表时的提示。

以 Study A 为例，正文记录入组 12 人，补图记录完整配对 8 人、实际进入单细胞分析 6 人。Chrome 实测覆盖点开候选原句、返回比较、跳过另一篇的一格、把“8 patients”编辑为“8 名患者”并采纳、保存后刷新。先前填写的关键对照、已采纳值和来源一起恢复。[三步截图](../../../README.md#从补图到跨篇比较)

### 从 PDF 补查缺项

单独的合成文件测试对比了只读已存摘录和启用 PDF 补查两种请求。入组列已有可查的证据卡时，使用已有候选。缺少单细胞分析人数时，从补充 PDF 第 1 页取回“6 patients”的原句，逐格采纳后重新读取比较记录可还原人工值和出处。替换文件后，旧句保留在保存的快照中，再次跳回或修改并采纳会触发来源检查。另将补件的第 1 页设为空白、第 2 页放入实际答案，限制检索页数后，页面显示无可读文字和未读页数，该字段保留空白。[API 与真实 PDF 用例](../../../app/tests/test_comparison_drafts.py) · [界面入口与范围提示测试](../../../app/tests/test_paper_comparisons.cjs)

### 其余功能的工程验收范围

| 功能 | 需要核对的结果 |
|---|---|
| 结论复核 | 从报告选中的确切位置打开复核，逐条查看图注、Methods 与干预相关片段及出处。保存时对应位置的文字、支持程度、判断理由和选定依据应一致。 |
| 图表覆盖 | 按正文图、补图分别查看报告生成时的输入，区分视觉观察、仅图注、未处理及失败。已识别整图与手动补入的图分开计数。补读后的观察可供下一次生成使用。 |
| 阅读快捷操作 | 导入结果只把该批缺正文的论文带入下载；读图笔记从当页的图进入证据卡；选择同课题的证据后，由读者保存到当前比较。 |
| PubMed 追踪 | 检查旧项目、暂停与归档、重启间隔、积压翻页、远端短响应、中途失败及并发标记已看的结果。历史未看 PMID 和最近成功时间应可恢复。 |
| 组会 PPTX | 按选图顺序读回导出的幻灯片，核对英文题目与四项可编辑文字、实际图像、论文与 PDF 页码，以及 PowerPoint 备注中的中文讲稿。 |
| 本机 Zotero 迁移 | 从本机数据库快照预览条目、子笔记和受管 PDF。核对重复项、所选主文件／补件与课题归属，并核对原 Zotero 数据。 |

**PubMed 的已执行验证。** 隔离课题中的 120 个新增合成 PMID 与一条旧未看记录形成 3 页积压。将第二页标记已看后保留 71 篇；模拟五天后重启，重叠结果没有重复出现。另用收紧后的模拟上游限制触发单日 PMID 拆分，中途断开不推进时间，重试取回全部结果。使用公开检索式 `botany[Title]`、2024 年 1 月的创建日期范围实际访问 NCBI，获得 10 个不同 PMID。[补查与范围拆分回归](../../../app/tests/test_pubmed_followups.py) · [分页、预览与启动检查回归](../../../app/tests/test_pubmed_followups.cjs)

**报告与图表。** 用合成报告的两处相同句子检查定位，指定出现次序后可修订相应句子并保存依据。另用模拟生成请求记录实际收到的观察。视觉读取失败而仍有图注的补图同时记录两种状态；之后加入的新观察不会改变旧报告的覆盖记录。[报告复核与读图记录回归](../../../app/tests/test_report_review.py)

**PPTX。** 用两篇合成论文的正文图、补图导出两页幻灯片。重新打开导出文件后，核对了顺序、独立可编辑的文字、嵌入图像的原始字节、每页出处及 PowerPoint 备注内的中文讲稿。图注在预览后变化或取消收藏时，导出会提示重新选图。[可编辑幻灯片与来源回归](../../../app/tests/test_figure_decks.py)

**本机 Zotero 迁移。** 在包含未合并 WAL 的合成数据库上，预览和迁入指定子笔记、主 PDF 和补件，比较了源文件指纹。另检查了同 DOI 已有论文、回收站重复条目、分页、预览过期和第二个 PDF 损坏时的恢复。[本机文库迁移回归](../../../app/tests/test_zotero_local.py)

**检索性能。** 128 篇、已有文字缓存时，整库无命中的完整请求中位数为旧实现 240.4 毫秒、当前 Python 97.3 毫秒、Rust 原型 101.0 毫秒。最后一篇单命中时，Python 为 109.0 毫秒、Rust 为 97.9 毫秒。首次提取另测两篇，三个实现的耗时范围重叠。发行版使用 Python 标准库，Rust 原型保留作可复现的对照。[设备、输入与全部结果](../../../app/tests/README.md#2026-11-20-全库检索与-rust-原型对照)

### 实际阅读的计时和复核

比较两种方式时，可固定同一批已读论文、研究问题、已保存的摘录和目标字段。由两名读者交叉安排手填或起草的先后顺序，从打开比较页计时，到最后一次核对原句并保存时停止。分别记录每位读者的用时、改值数／给出的候选数，以及另一名读者回原页确认支持的引文数／实际采用的引文数。单列漏提、错列和缺少补件，记录纯翻译或单位格式调整。上面的 17 项是合成材料的工程结果，真实读者用时和修改率有待这项测量。
